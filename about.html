How it works & what it models

An honest description of the abstraction behind TritLogic — for anyone who wants to trust, teach with, or cite it.

TritLogic is an in-browser simulator for balanced-ternary digital logic. It's an unusually complete tool in a near-empty niche — a Logisim-style environment for the three-valued world rather than the binary one — aimed at the ternary / multi-valued-logic (MVL) curious: students, CS educators, and hobbyists. It is not a claimed world-first, and it is not production EDA.

The trit

Every signal is a balanced trit — one of three values: T = −1, 0, and +1. Balanced ternary is symmetric about zero, so negative numbers need no sign bit and no two's-complement: you negate a number by flipping every digit. Base 3 is also the integer base closest to e, the radix-economy optimum, so a trit carries ≈1.58 bits. Two extra signal levels ride alongside the trits for buses: Z (high-impedance — a tri-state driver not driving) and X (contention — strong drivers disagree).

The model: switch / gate level

TritLogic simulates at the idealised-trit, gate level — the ternary analogue of a binary logic simulator. Values are discrete; there are no continuous voltages. The core pieces:

  • Combinational solver. An event-driven engine settles the network to a steady state: each component is evaluated, and a change on its output wakes only its downstream consumers (with an oscillation-guard budget for ill-formed feedback). On a well-formed acyclic circuit it settles in one evaluation per component.
  • Sequential engine. Clocked elements (flip-flops, registers, RAM, program counters) advance with a 4-phase step: tick the clock → settle → latch on the edge → settle. One instruction or state transition per step.
  • Hierarchy. Any selection can be packed into a reusable subcircuit; subcircuits nest and are simulated structurally, all the way down to MIN/MAX and the unary inverters — so a CPU can be opened down to gates.
  • Timing & hazards (optional). A timing mode gives each component an integer propagation delay and replays the settle on an event wheel, so reconvergent paths with unequal delay surface real dynamic and static hazards (glitches). Delays are abstract units, not nanoseconds; a subcircuit is charged its internal critical-path delay.

What it models

  • Three-valued logic over {−1, 0, +1}
  • Gate behaviour (STI/PTI/NTI, MIN, MAX) & truth tables
  • Ternary arithmetic, registers, RAM/ROM, an ALU, a microcoded CPU
  • Tri-state buses with Z / X resolution
  • Propagation delay & glitch (hazard) behaviour, in abstract time

What it does not model

  • Continuous voltages, thresholds, or noise margins
  • Analog noise, drift, or device physics
  • Real-world timing in seconds (delays are unit-less)
  • Optical / photonic power or loss
  • Power, area, or fabrication effects

Continuous-voltage / analog behaviour is a separate, future direction (an analog mode); the physical photonic side lives in its own workspace.

The logic minimizer

The built-in minimizer is the balanced-ternary analogue of binary Quine–McCluskey / K-map SOP reduction. Given a truth table it produces a compact MAX-of-MIN expression over MIN / MAX / STI / PTI / NTI: it covers the f = +1 and f = 0 onsets independently (decoder literals act as value-subset boxes), enumerates prime implicants, greedy-covers by lowest cost-per-new-minterm, and returns whichever of {minimized, canonical} is cheaper — so the result is never worse than the naive form. It can also materialise the minimized expression as a real placed subcircuit of gates.

Correctness

The simulator ships with a self-test suite (130+ pure-function checks) covering conversions, every gate's truth table, the full adder and ripple addition, flip-flop / register / RAM semantics, each kit subcircuit's gate-level equivalence to its native twin, the assemblers, live CPU programs, and the minimizer. They verify the math, not the UI — you can run them yourself from the Tests button in the app. The source is viewable on GitHub.

How to cite

If TritLogic is useful in a paper, course, or write-up, a citation is appreciated. The repository carries a CITATION.cff (GitHub shows a “Cite this repository” button). A plain-text software citation: 

SK000001. (2026). TritLogic — a balanced-ternary logic & circuit simulator (Version 1.0.0) [Software]. https://tern-pi.vercel.app

A versioned, archival DOI (e.g. via Zenodo) can be minted when a release is tagged and added to the citation. Author attribution in the citation above is a GitHub-handle placeholder pending a real name.
